## 처음 설정하기

비밀 값 두 개를 깃허브 저장소에 등록하면 끝입니다. 두 값은 비밀번호와 같으니 다른 곳에 붙여 넣지 마세요.

### 1. 슬랙 웹훅 주소 (`SLACK_WEBHOOK_URL`)

1. slack.com에서 개인 워크스페이스를 만들고, 브리핑을 받을 채널을 만듭니다.
2. https://api.slack.com/apps → **Create New App** → **From scratch** → 이름을 적고 워크스페이스를 고릅니다.
3. 왼쪽 메뉴 **Incoming Webhooks** → 스위치를 **On**.
4. 아래의 **Add New Webhook to Workspace** → 채널 선택 → **허용**.
5. `https://hooks.slack.com/services/...`로 시작하는 주소를 복사합니다.

### 2. Claude 구독 토큰 (`CLAUDE_CODE_OAUTH_TOKEN`)

AI는 Claude 유료 구독 계정으로 호출합니다. API 요금은 따로 들지 않고 구독 사용량에서 차감됩니다.

1. PC 터미널에서 `claude setup-token`을 실행합니다.
2. 브라우저에서 로그인하면 터미널에 토큰이 출력됩니다. 복사합니다.
3. 토큰은 1년간 유효합니다. 1년 뒤 브리핑이 "생성 실패"로 오면 다시 발급해 등록하세요.

### 3. 깃허브에 등록

저장소 페이지 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| Name | Secret |
|---|---|
| `SLACK_WEBHOOK_URL` | 1번에서 복사한 주소 |
| `CLAUDE_CODE_OAUTH_TOKEN` | 2번에서 복사한 토큰 |

### 4. 바로 한 번 보내 보기

저장소 페이지 → **Actions** 탭 → 왼쪽의 **daily-briefing** → **Run workflow** → **Run workflow**.
5~10분 뒤 슬랙에 브리핑이 도착합니다.

## 뉴스를 고르는 기준

1. 18개 매체의 최근 24시간 주요 기사를 모읍니다(하루 약 450건).
2. AI가 같은 사건을 다룬 기사를 하나로 묶고 분류합니다.
3. 프로그램이 아래 규칙으로 통과 여부를 계산합니다. 이 부분은 AI가 정하지 않으므로 날마다 기준이 같습니다.

| 분류 | 통과 조건 | 하루 최대 |
|---|---|---|
| 경제·IT | "큼" 또는 "중간" 단계면 매체 1곳만 다뤄도 통과. "일상" 단계는 제외 | 10건 |
| 그 외 세계 뉴스 | 매체 3곳 이상, 소속 지역 2곳 이상 | 3건 (국내 포함) |
| 그 외 한국 국내 뉴스 | 한국 매체 2곳 이상 | 위 3건에 포함 |

- 중국·일본·유럽은 통과한 경제·IT 뉴스가 있으면 각 1건씩 반드시 들어갑니다.
- 연예, 스포츠 결과, 단순 사건·사고, 정치인 말싸움, 광고성 기사, 칼럼은 뺍니다.
- 이미 보낸 소식은 새로운 결정·발표·숫자가 나왔을 때만 "(이어지는 소식)"으로 다시 보냅니다.
- 큰일이 없는 날은 적게 보냅니다. 개수를 채우려고 덜 중요한 뉴스를 넣지 않습니다.

## 기준 바꾸기

`config/settings.json`의 숫자를 고치면 됩니다. 깃허브 화면에서 파일을 열고 연필 아이콘을 눌러 바로 고칠 수 있습니다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `econ.max` | 경제·IT 하루 최대 건수 | 10 |
| `econ.guaranteed_regions` | 한 자리씩 보장하는 지역 | 중국, 일본, 유럽 |
| `general.max` | 그 외 뉴스 하루 최대 건수 | 3 |
| `general.min_outlets` | 세계 뉴스가 통과하려면 다뤄야 하는 매체 수 | 3 |
| `general.min_regions` | 그 매체들의 소속 지역 수 | 2 |
| `general.kr_min_outlets` | 국내 뉴스가 통과하려면 다뤄야 하는 한국 매체 수 | 2 |
| `window_hours` | 몇 시간 안의 기사를 볼지 | 24 |
| `history_days` | 이미 보낸 소식을 며칠간 기억할지 | 7 |
| `model` | 사용할 AI 모델 | claude-haiku-5-5 |

매체를 넣거나 빼려면 `config/sources.json`을 고칩니다.

보내는 시각은 `.github/workflows/daily.yml`의 `cron: "0 22 * * *"`에서 바꿉니다. 시각은 UTC 기준이라
한국 시간에서 9시간을 뺀 값을 적습니다(22시 = 한국 오전 7시).

## 브리핑이 안 왔을 때

- 슬랙에 **"브리핑 생성 실패"** 메시지가 왔다면 그 안에 이유가 적혀 있습니다.
- 아무것도 안 왔다면 저장소의 **Actions** 탭에서 그날 실행 기록을 확인합니다. 빨간 표시가 있으면 눌러서 어느 단계에서 멈췄는지 볼 수 있습니다.
- 60일 넘게 저장소에 변화가 없으면 깃허브가 예약 실행을 끄는데, 이 프로그램은 매일 브리핑을 저장하므로 해당되지 않습니다.

## 알아 둘 점

- 깃허브의 예약 실행은 정시보다 5~30분 늦을 수 있습니다. 그래서 7시에 예약해 두었습니다.
- 로이터, AP, 차이신, NHK 월드는 주요 기사 목록을 직접 제공하지 않아 구글 뉴스의 매체별 최신 목록으로 대신합니다.
- AI가 쓴 요약에는 오류가 있을 수 있습니다. 투자 판단 전에는 원문 링크를 확인하세요. 이 브리핑은 투자 조언이 아닙니다.
- 지난 브리핑은 `archive/` 폴더에 날짜별로 쌓입니다(슬랙 무료 요금제는 최근 90일만 보여 줍니다).
